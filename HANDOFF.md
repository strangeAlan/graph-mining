# Handoff: state of the project and open directions (11/15)

For whoever continues the innovation part. Read together with `README.md` (layout, commands) and `notes/LOG.md`
(chronological record of every run and decision).

## 1. What is done

- **Course base requirement (done).** Node classification on Cora, Citeseer (public Planetoid split, 10 seeds) and
  ogbn-products (official split + OGB evaluator, 3-5 seeds) with MLP, label propagation, GCN, GAT, APPNP, GraphSAGE, SIGN,
  each with and without Correct & Smooth. Numbers match the published ones on the small graphs; on ogbn-products MLP 60.3
  (OGB 61.1), GraphSAGE 78.8 (OGB 78.5), SIGN 78.0 (OGB 80.5, gap unexplained after three configurations).
- **Report draft (v1).** `report/report.tex`, ACM sigconf, English: intro, related work, data, methods, setup, reference results,
  CoE results/analysis. Tables are generated by `scripts/make_tables.py` from `results/`.
- **Innovation attempt: Cooperation of Experts (CoE) for node classification.** CoE (Wang et al., ICML 2025; the user is a
  co-author; code github.com/strangeAlan/CoE) combines expert class distributions with a learned cooperation matrix and a
  large-margin loss; it was designed for heterogeneous multiplex graphs. Our adaptation (`src/graphmine/ensemble.py`):
  - experts differ in the information they use: MLP (features), label propagation (labels + graph), GNNs;
  - the cooperation matrix is fitted on **out-of-fold** expert predictions (in-sample predictions are ~100% correct with
    20 labels per class, and LP returns its training labels verbatim, so the original in-sample fit learns nothing);
  - initialised as accuracy-weighted voting, L2 pull to that initialisation, (gamma, reg) chosen on validation;
  - optional one round of ensemble self-training (CoE predictions above tau become pseudo-labels for every expert).

## 2. Verified findings (test accuracy, %)

| | Cora | Citeseer | ogbn-products |
|---|---|---|---|
| best expert, chosen on validation | 82.3 (GAT) | 71.1 (APPNP) | 77.9 (SIGN) |
| best expert on test (oracle) | 83.2 (APPNP) | 72.0 (GAT) | 77.9 (SIGN) |
| best expert + C&S | 83.2 | 72.0 | 78.8 (SIGN) / 79.0 (SAGE) |
| accuracy-weighted voting | 82.9 | 71.6 | 78.9 |
| stacking (CoE without margin term) | 83.0 | 71.5 | 79.6 |
| CoE | 82.7 | 71.6 | 79.5 |
| CoE without the LP expert | – | – | 78.3 |
| single-model self-training | 82.7 (GAT) / 84.0 (APPNP) | 72.8 (APPNP) / 73.5 (GCN) | 79.4 (SIGN, one round; 80.0 after two) |
| CoE + ensemble self-training | 83.7 | 72.3 | 80.8 |

1. On ogbn-products CoE beats the best expert by 1.6 points and SIGN + C&S by 0.75; seed std there is 0.1-0.2.
2. Most of that gain comes from the label-propagation expert: without it (MLP + SIGN) CoE is only +0.2 over SIGN.
   CoE is therefore best described as a learned way to combine label propagation with feature-based models,
   and it beats C&S (the usual way to do this) on ogbn-products.
3. On Cora/Citeseer CoE equals voting: above the validation-chosen expert, below the test-best expert. With 20 labels per
   class the validation search keeps the cooperation matrix close to voting (Citeseer picks the strongest pull every seed).
   With a random 60/20/20 split (1,624 labels on Cora) the matrix is free but CoE still only ties the best experts
   (86.5 vs 86.4 val-chosen / 87.0 test-best): the reason is that the GNN experts make similar errors, not the label budget.
4. The CoE large-margin term never beats plain stacking (gamma = 0).
5. Ensemble self-training lifts every expert (Cora APPNP 83.2 -> 84.3, products SIGN 77.9 -> 80.5). On the small graphs it is
   no better than single-model self-training; on products SIGN on CoE pseudo-labels beats SIGN on its own pseudo-labels after
   one round (80.5 vs 79.4). Pseudo-label precision: Cora 0.84, Citeseer 0.72, products 0.91.
   Caveat: on products validation accuracy stays ~93% across self-training rounds while test rises, so validation-based
   selection always discards self-training there (the report uses a fixed single round for both methods).
6. The LP-agreement filter for self-training (`lpst`) is no better than plain confidence (`st`).

## 3. Pitfalls already hit

- **Shared GPUs.** cv-3Drecon runs on the same two A100s and has priority. On 11/14 a 36 GB products job made its COLMAP run
  fail with CUDA OOM (recovered by re-running). Check `nvidia-smi` for other users before every launch.
- **`pgrep -f` / `pkill -f` self-match.** A guard script started from a shell whose command text contained its pattern killed all
  runs on 11/14. Kill by PID; put watcher scripts in files.
- **ogbn-products is slow.** GraphSAGE/GCN full-batch: 16-30 min per fit, ~36 GB. One CoE run (3 experts, 3 folds, + self-training)
  takes ~3 h. Validation accuracy (~93%) is far above test (~78%) because of the sales-rank split.
- **LP coverage.** Nodes in components without training labels get no label mass; LP now returns a uniform row with
  `has_signal = False` (an all-zero row used to be read as class 0). Citeseer: 48 isolated nodes, many unlabelled components.
- **Mirrors.** Tsinghua conda/PyPI mirrors return 403 on this server; use Aliyun PyPI and the NJU conda mirror.

## 4. Open directions (my assessment, not tested)

1. **Node-wise cooperation.** CoE's matrix is the same for every node. Finding 2 suggests the right weight for the LP expert
   depends on the node (label mass received, degree, distance to labelled nodes). A small gate that predicts per-node expert
   weights from such statistics, trained out-of-fold, is the most natural method contribution. Check prior work on
   mixture-of-experts gating for GNNs before claiming novelty.
2. **More diverse experts on ogbn-products.** Add GraphSAGE and LP with other propagation strengths; cheap to try if GPU time allows.
3. **Label-rate sweep on ogbn-products** (subsample the training labels) to show where fusion stops helping; directly
   supports or refutes finding 3.
4. Not pursued: LLM / text-attributed approaches (the course datasets have no raw text), more seeds on the small graphs.
